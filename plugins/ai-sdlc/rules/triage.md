# Input Triage Rules — 输入分流规则（v0.12.0）

> 触发条件：每一条用户输入到达时（UserPromptSubmit 之后、任何行动之前）。
> 目标：把用户提供的内容提炼区分为**需求/ISSUE**、**补充信息**、**临时任务**三类，
> 需求/ISSUE 统一走 SDLC 流程，临时任务不经流程单独处理，补充信息融入当前周期。
> 配套：`.sdlc/quick-tasks.json` 队列（MCP 受控读写，agent 禁改）、MCP `quick_task`
> 工具（v0.13.0：用户入口为自然语言，官方 CLI 不支持自定义 slash 命令）。
> 完整标准见 `docs/lifecycle.md`。

## 三分类定义（先分类，再行动）

| 类别 | 判定特征 | 执行路径 |
|------|---------|---------|
| **REQ 需求/ISSUE** | 新功能、缺陷、性能问题、改进——将改变产品行为/交付物，值得产出工件链 | **统一走 SDLC 流程**：按当前阶段推进（intent → spec → plan → diff+tests → PR → incident） |
| **SUPP 补充信息** | 针对当前周期的澄清、Open questions 的回答、范围/约束/背景补充 | **融入当前阶段工件**：回答进 intent.md 对应章节（移除或标记该条 Open question）；范围/约束更新 intent.md / spec.md；实施细节更新 plan.md——不新开流程 |
| **QUICK 临时任务** | 一次性小事，与当前需求无交付物级关联：查资料、解释代码、改文档措辞、跑一次脚本、临时配置 | **不走 SDLC 流程**，单独处理（见下） |

## 判定规则（按优先级）

1. **当前停在 awaiting_answers 且消息内容对应 Open questions** → SUPP（把答案融入 intent.md 并移除/标记该条问题）。
2. **消息明确指向当前周期的工件或需求上下文**（"这个功能还要…"、"上一条的补充是…"）→ SUPP。
3. **消息描述了新的痛点/想法/缺陷，且会产出交付物或改变代码行为** → REQ。
4. **消息是一次性操作，不产生工件链交付物**（问询、查看、解释、临时小改）→ QUICK。
5. **一句话里混有多类内容** → 拆分处理：REQ 部分走流程，QUICK 部分（若周期进行中）登记排队，并向用户说明两部分各自的去向。
6. **拿不准时**：宁可问用户一句话确认（"这是要并入当前需求，还是独立的小事？"），不得擅自混流。

## QUICK 临时任务的执行协议

- **当前无进行中周期**（工作区无 intent.md / spec.md / plan.md）→ **直接处理**：做完即止，不落任何 SDLC 工件、不触发阶段语义、不写 intent/spec/plan。
- **周期进行中**（工作区存在当前周期工件）→ **登记排队，不立即处理**：
  1. 用 MCP 工具 `mcp__sdlc-orchestrator__quick_task({ action: "add", desc: <一句话描述> })` 登记（用户说「记个临时任务/这事排队」即触发）。
  2. 回复用户：已登记排队，**当前 SDLC 流程走完后统一处理**——二者不混淆、不交叉。
  3. 队列中的任务**不得**在周期结束前写进当前周期的任何工件或代码改动。
- **周期结束的时机**：maintain 闭环归档、`new_cycle`、`task_close` 之后工作区回到干净状态——此时 Stop/UserPromptSubmit/SessionStart 会提示队列内容，逐条处理即可（处理后 `quick_task({action:"done", id})`）。
- **用户显式优先**：用户明确要求"现在先处理 XX"（临时任务）→ 允许立即处理（`quick_task({action:"run", id})` 或直接执行），但处理结果仍**不得混入当前周期工件**；完成后回到周期原阶段继续。

## 硬约束

1. **REQ 必须走流程**——不得为跳过 intent/spec/plan 而把需求伪装成临时任务（发现特征：改业务代码、产生交付物、影响测试）。
2. **QUICK 不落 SDLC 工件**——临时任务不写 intent.md / spec.md / plan.md / REVIEW.md，不推进阶段。
3. **SUPP 只更新既有工件**——补充信息不新开周期（确属新需求时按 REQ 处理并向用户说明）。
4. **队列文件 agent 禁改**——`.sdlc/quick-tasks.json` 是运行时状态（PreToolUse block），只能经 MCP `quick_task` 工具修改（用户亦可在编辑器中直接改）。
5. **排队提醒必须转达**——队列非空且周期进行中时，回复用户须包含排队状态（多少条、何时处理）。

## 反模式

- ❌ 把临时任务顺手做进当前周期的 diff——审计链被污染（"二者不混淆"是硬边界）。
- ❌ 把用户对 Open questions 的回答当作新需求另开周期——SUPP 直接融入即可。
- ❌ 队列空转：周期早已结束却从不提示用户处理排队任务。
- ❌ 一次性小事也写 intent.md——流程膨胀是 SDLC 被弃用的第一原因。
