# /design-bridge — 模块间衔接设计与实现

## 输入

用户参数：$ARGUMENTS

- 两个待衔接模块名（`<module-a> <module-b>`）
- 若参数为空：停止并列出可衔接的候选模块对（从 snapshot 的
  模块清单推断）

## 流程

1. **契约分析**：读两模块现有接口（导出 / 类型 / 数据形状），
   列出不对齐点（命名 / 语义 / 错误模型 / 数据所有权）
2. **契约设计**：衔接层的数据契约 + 转换规则 + 错误传播策略
   （一方的失败不得静默吞掉）；产出 `docs/design/bridge-<a>-<b>.md`
3. **标记**：`//TODO#NNN bridge: <a>→<b> <职责> [agent:default]`
   + `[depends:]` 双方前置改动
4. **实现**：转 `/coding`——衔接代码只做转换与传播，不藏业务逻辑
5. **评审 + 测试**：`/review` 重点看契约边界；集成路径补
   `/integration-test <a> <b>`
6. **收口**：advance

## 标记绑定

- 桥接标记带 `bridge:` 前缀描述；双向桥接要拆两个独立标记

## 产出物

- `docs/design/bridge-<a>-<b>.md`（契约文档，必需）
- 衔接层源码 + 契约级测试（含错误传播用例）

## 反模式（禁止）

- ❌ 衔接层写业务判断（职责漂移，日后无法测试）
- ❌ 契约只定义 happy path（错误传播不设计 = 故障排查地狱）
- ❌ 改动 a/b 内部来迁就衔接（应优先适配器；改内部要回各自模块流程）
- ❌ 双向同步复制数据而不声明唯一所有方（数据分叉）
