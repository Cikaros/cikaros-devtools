# /design-bottomup — 自底向上设计与实现

## 输入

用户参数：$ARGUMENTS

- 目标能力描述（最终要能做什么）
- 若参数为空：停止并询问

## 流程

1. **底层工具**：识别最小可复用单元（纯函数 / 无状态组件），逐个实现
   并创建 `//TODO#NNN <底层单元> [agent:default]`（此时不急于定总体架构）
2. **向上组合**：组合底层单元为高阶能力；每层组合创建上层标记并
   `[depends:]` 底层标记
3. **架构反推**：组合稳定后，从实际形态反推架构文档
   `docs/design/<slug>.md`（记录真实依赖图而非设想图）；与既有 ADR
   冲突时提新 ADR
4. **评审**：转 `/review`（重点核对反推后的依赖方向仍单向）
5. **收口**：advance + CHANGELOG

## 标记绑定

- 底层→上层：标记的 depends 树即组合顺序；
  resolve 依旧全部走 advance 自动闭环

## 产出物

- 底层工具库 + 组合层源码 + 各层测试
- `docs/design/<slug>.md`（反推后的真实架构，必需）

## 反模式（禁止）

- ❌ 反推阶段懒得写文档（自底向上最大的坑就是架构只存在于代码里）
- ❌ 底层单元带隐藏全局状态（组合阶段必然踩坑）
- ❌ 组合层直接绕过底层接口改动底层内部（组合契约失效）
- ❌ 依赖图出现环（反推阶段必须重新切分）
