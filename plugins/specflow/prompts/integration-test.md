# /integration-test — 集成测试

## 输入

用户参数：$ARGUMENTS

- 待验证的模块组合（`<a> <b>` 或 `a,b,c`）；`all` = 全部关键链路
- 若参数为空：从 `.specflow/todo-state.json` 的 depends 树推断强耦合
  模块对，列出候选链路供选择

## 流程

1. **链路分析**：从 depends 树 + 调用关系识别跨模块链路；
   每条链路定义「起点输入 → 终点断言」（穿过所有中间模块）
2. **登记标记**：每条链路创建
   `//TODO#NNN itest: <a>→<b>→<c> [agent:default]`
3. **环境策略**：外部依赖（DB / 网络 / 第三方 API）用契约替身
   （contract stub），替身行为记录在测试夹具内；不 mock 内部模块
4. **生成用例**：每条链路至少 3 类——正常流转 / 中间模块失败传播 /
   边界数据穿透；失败传播必须断言（不许静默吞）
5. **执行**：跑集成套件；结果进 `docs/changes/test-report-<date>.md`
   集成一节
6. **收口**：advance 自动 resolve itest 标记

## 标记绑定

- `itest:` 前缀；depends 指向各模块实现标记（实现齐了才轮到集成）

## 产出物

- 集成测试文件（`tests/integration/` 或框架约定位置）
- 契约替身夹具（可复用）
- 测试报告集成章节

## 反模式（禁止）

- ❌ 集成测试里逐模块 mock 到只剩胶水（那是单测的叠加，不是集成）
- ❌ 断言只看 200/OK 不看数据贯穿（链路语义没验证）
- ❌ 外部服务真连线上环境（用契约替身或本地沙盒）
- ❌ 集成失败不定位就重跑祈求通过（flaky 也要登记 FIXME）
- ❌ 链路覆盖 100% 模块对（抓关键链路，不做组合爆炸）
